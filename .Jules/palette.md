## 2024-11-20 - Accessible Truncated Text
**Learning:** When visually truncating text in the UI (e.g., using ellipses like `...` via JavaScript `substring` or CSS `text-overflow`), it creates an accessibility issue where the full content is hidden from screen readers and mouse users.
**Action:** Always pair visually truncated text with an accessible `title` attribute or a tooltip containing the full text to ensure accessibility and usability, as implemented for job IDs and tasks in `app.js`.
## 2024-06-15 - Accessible Dynamic Data Containers & Scrollable Regions
**Learning:** In a dashboard where data (like job queues or JSON payloads) is updated asynchronously, setting `aria-live="polite"` on the containers is vital so screen readers can narrate updates. In addition, when using `<pre>` tags (or any other container) with `overflow-x: auto` to format code or structured data, these regions become inaccessible to keyboard users unless explicitly given `tabindex="0"`. A visible focus state (`:focus-visible`) and an `aria-label` must also be provided so the user knows when the region is focused and what it contains.
**Action:** When inspecting interfaces with dynamically updating logs, code blocks, or data panels, specifically verify the presence of `aria-live` for announcements, and check that any element with `overflow: auto` or `overflow-x: auto` is focusable, visibly indicates focus, and is properly labeled.
